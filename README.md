# PharmaNet: Supply Network Optimization & Resilience

> **All data in this project is synthetic.** It is generated by a seeded random process to
> resemble a pharma distribution network. No result here describes a real company, product, or
> network.

PharmaNet designs a pharma distribution network (plants → distribution centers → demand regions,
with cold-chain products and regulatory site qualification) and then stress-tests it. It runs end
to end from one command, and every number it reports is generated, validated, and traceable to a
config and a git commit.

```
 synthetic data ─▶ forecast + safety stock ─▶ MILP network design ─▶ simulation ─▶ graph risk ─▶ results.md
   (Phase 2)          (Phase 3)                (Phase 4)             (Phase 5)     (Phase 6)     (Phase 7)
```

## Headline results (base instance, synthetic)

| | |
|---|---|
| **MILP vs greedy heuristic** | **16.6%** mean cost saving (range 10–24%) across 10 generated networks, mostly from DC choice |
| **Forecast accuracy** | **9.2%** WAPE improvement over seasonal naive with a global ETS model on an out-of-sample holdout (7.2% with per-series selection, which overfits) |
| **Demand uncertainty** | 500 Monte Carlo scenarios: mean service 100%, worst 99.2%; cost p5–p95 $4.07M–$4.21M |
| **Resilience** | Worst single-node failure puts **28.5%** of demand at risk. N-1 DC capacity plus dual-qualifying single-source products cuts it to **15.5%** (−46%) for +12.5% network cost |
| **Scale** | 2,552 variables (8 binary), 2,320 constraints; proven optimal in ~1 s with HiGHS |
| **Stochastic design** | Two-stage model (107k variables, 42 scenarios) buys a larger DC: 0.39% lower expected cost out of sample and +3.4 pts mean service under outages, for +4.1% normal-year cost. With demand uncertainty alone it matches the deterministic design |

Full generated report: [docs/results.md](docs/results.md). Each figure there has its source file and caveat.

## What's inside

| Stage | Method | Code |
|---|---|---|
| Data | Seeded generator: trend × seasonality × lognormal noise, intermittent series, cold chain, plant qualification, capacities sized from demand | [`data/`](src/pharmanet/data) |
| Forecasting | Seasonal naive, damped Holt-Winters ETS, SARIMA; rolling-origin backtest; WAPE/MAPE/bias; per-series or global selection with an honest holdout | [`forecasting/`](src/pharmanet/forecasting) |
| Safety stock | $z\sqrt{L\sigma_d^2 + \bar d^2\sigma_L^2}$ with backtest RMSE. Lead times start from the fastest feasible path, then are refined from the chosen network | [`inventory/`](src/pharmanet/inventory) |
| Network design | Pyomo MILP: open DCs + flows; qualification, DC/cold capacity, unmet penalty; strong-link constraints; optional single-sourcing, max DCs, N-1 resilience | [`optimization/`](src/pharmanet/optimization), [formulation](docs/formulation.md) |
| Benchmark | Greedy heuristic; saving split into DC choice vs routing; multi-instance benchmark | [`baseline.py`](src/pharmanet/optimization/baseline.py) |
| Validation | Independent check of every solution (flow balance, capacities, qualification, closed DCs, recomputed objective) | [`validate.py`](src/pharmanet/optimization/validate.py) |
| Simulation | Design fixed, flows re-solved as LP: correlated Monte Carlo demand, plant/DC/cold-lane outages, sensitivity with regret | [`simulation/`](src/pharmanet/simulation) |
| Graph risk | Flow graph (exposure via proportional tracing) and capability graph (dominator-based single points of failure); cross-checked against simulation; mitigations priced | [`graph/`](src/pharmanet/graph) |
| Stochastic design | Two-stage extensive form with demand + outage scenarios; RP, EEV, VSS, WS, EVPI; out-of-sample comparison | [`stochastic.py`](src/pharmanet/optimization/stochastic.py) |
| Neo4j | CSV + `import.cypher` bundle and 5 business Cypher queries, each with an independent pandas answer; verified on live Neo4j 5.26 | [`neo4j_export.py`](src/pharmanet/graph/neo4j_export.py) |
| Viewer | Streamlit app over a run's outputs (network map, distributions, risk bounds, stochastic comparison) | [`viewer/`](src/pharmanet/viewer) |

Methods, assumptions, and caveats: [docs/methodology.md](docs/methodology.md). MILP math, matching the code constraint by constraint: [docs/formulation.md](docs/formulation.md).

## Quickstart

Requires Python 3.11 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync                                              # create the environment
uv run pharmanet run-all -c configs/base.yaml        # everything, ~4–6 min -> outputs/base/results.md
uv run pharmanet run-all -c configs/base.yaml --publish   # also update docs/results.md
```

Individual stages (each reads the previous stage's files from `outputs/<run_id>/`):

| Command | Does | Time (base) |
|---|---|---|
| `pharmanet generate` | synthetic data | <1 s |
| `pharmanet forecast` | backtest, model selection, 12-month forecast, safety stock | ~40–80 s |
| `pharmanet optimize` | MILP, safety-stock refinement, greedy benchmark | ~3 s |
| `pharmanet simulate` | 500 Monte Carlo + 38 disruptions + 15 sensitivity re-designs | ~40 s |
| `pharmanet graph` | graph risk, cross-check, mitigations, GraphML export | ~20 s |
| `pharmanet stochastic` | two-stage stochastic design, VSS/EVPI, out-of-sample comparison | ~3 min |
| `pharmanet neo4j-export` | Neo4j CSVs, `import.cypher`, `queries.cypher`, expected answers | ~1 s |
| `pharmanet neo4j-verify` | run the queries in a live Neo4j container and diff against the pandas answers | ~5 s |
| `pharmanet benchmark` | MILP vs greedy on N generated networks | ~15 s |
| `pharmanet report` | regenerate `results.md` from existing outputs | <1 s |
| `pharmanet check-config` | validate a config file | <1 s |
| `pharmanet view` | open the Streamlit results viewer (`uv sync --extra viewer`) | — |

All commands take `-c <config>` and `--run-id <name>`. Every parameter (sizes, costs, seeds, solver, service level, scenario counts) lives in [`configs/`](configs); nothing is hardcoded. Changing the solver to Gurobi is one line (`optimization.solver.name`); that path is wired up but untested here.

## How it's validated

- **165 tests** (`uv run pytest`, ~30 s), plus an opt-in live Neo4j test (`pytest -m neo4j`), run in CI with ruff and strict mypy on every push.
- **Hand-verified regression instance** (2 plants × 3 DCs × 3 regions × 2 products): all 7 designs enumerated on paper in [formulation.md](docs/formulation.md#regression-instance-hand-verified). Tests assert the exact optimum (2,850, DCs {D1, D2}), every alternative, and hand-derived disruption costs.
- **Property tests:** more demand never costs less; removing a DC never costs less; MILP ≤ greedy; strong-link constraints leave the optimum unchanged; sensitivity regret ≥ 0.
- **Leakage guard:** the backtest model at origin *t* provably sees only months before *t*.
- **Independent solution validation** on every solve, including the objective recomputed from flows.
- **Cross-module consistency:** graph lower bound ≤ simulated loss ≤ graph upper bound, checked for every node.
- **Provenance:** each run writes `manifest.json` (config sha256, git commit, timings), and `results.md` is generated from output files only.

## Limitations (stated, not hidden)

- Synthetic data. The structure is realistic, but the magnitudes are not calibrated to any real network.
- Single-period (annual) design: no inventory dynamics, outage timing, or production scheduling.
- Safety stock is added to annual flow (it reserves capacity for the buffer). This is a standard strategic-model simplification.
- Monte Carlo treats monthly forecast errors as independent (√12 scaling), which likely understates annual spread.
- Dual-qualification cost (tech transfer, regulatory approval) is not modelled.
- Gurobi/CBC solver paths are untested. HiGHS is the tested default.
- The stochastic design's value depends on assumed outage probabilities and the unmet-demand penalty.

## Troubleshooting

**`ModuleNotFoundError: No module named 'pharmanet'` on macOS.** When the project sits in an
iCloud-synced folder (e.g. `~/Documents`), iCloud marks dot-files such as `.venv/**` as hidden,
and recent Python releases skip hidden `.pth` files, which breaks the editable install. The fix
used here keeps the environment in `venv.nosync/` (iCloud ignores `*.nosync`), with `.venv` as a
symlink to it:

```bash
rm -rf .venv venv.nosync && uv venv venv.nosync && ln -s venv.nosync .venv && uv sync
```

Alternatively, move the project outside iCloud-synced folders.
